## Task 1 — Formal Security Audit & Foundry Invariant Tests

### What this adds
The existing `Vault.t.sol` covers 3 unit tests and 1 basic fuzz test. We need **invariant (stateful) tests** — Foundry's most powerful security primitive — that run thousands of random call sequences against the vault and prove that critical safety properties can never be violated, no matter what order calls arrive in.

### Proposed Changes

#### [NEW] `test/VaultInvariant.t.sol`

Five invariants will be proven:

| Invariant | What it proves |
|---|---|
| `invariant_vaultSolvency` | Vault ERC20 balance ≥ sum of all locked swap amounts (no funds can leak) |
| `invariant_noDoubleFinalization` | A swap cannot be both `isExecuted=true` AND `isRefunded=true` simultaneously |
| `invariant_executedSwapIsIrreversible` | Once `isExecuted`, no state mutation can re-open the swap |
| `invariant_onlyCounterpartyCanExecute` | `executeSwap` always reverts when called by any address other than `swp.counterparty` |
| `invariant_onlyInitiatorCanRefund` | `refundSwap` always reverts when called by any address other than `swp.initiator` |

Additional fuzz tests added to `Vault.t.sol`:
- `testFuzz_SignatureReplay` — proves that a valid `(swapId, score)` signature cannot be replayed on a different `swapId`
- `testFuzz_FairTradeEdgeCases` — covers zero-value bundles and `MAX_UINT` amounts through `_isFairTrade`

Documents: known risks, mitigations applied, invariant test results, and gas profiling table.

## Task 2 — Chainlink Functions Integration

### What this adds
Currently `riskEngine.js` uses **mock USD values** supplied by the frontend caller to evaluate L1 Value Drain. This is trivially gameable. We replace it with a **real decentralized valuation** powered by Chainlink Functions — a DON-executed JavaScript runtime that fetches floor prices from game market APIs (OpenSea, DMarket, or proprietary studio APIs) and returns them on-chain.

### Architecture

```
Frontend  ─→  commitSwap()  ─→  UniversalVault
                                     │
                              FairValueGuard.sol
                              (Chainlink Consumer)
                                     │
                         Chainlink DON executes JS source
                                     │
                         gameAssetSource.js
                         fetches OpenSea/DMarket API
                                     │
                         fulfillRequest() callback
                                     │
                         Result stored on-chain, used
                         by _isFairTrade() in executeSwap
```

### Proposed Changes

#### [NEW] `src/FairValueGuard.sol`
- Extends `FunctionsClient` from `@chainlink/contracts`
- `requestAssetValuation(tokenId, contractAddress)` — sends a Chainlink Functions request
- `fulfillRequest(requestId, response, err)` — stores the returned floor price (in USD, 8 decimals)
- `getLatestValuation(tokenId)` — read-only getter used by `UniversalVault`

#### [NEW] `chainlink-functions/gameAssetSource.js`
JavaScript source executed by the Chainlink DON:
```javascript
// Fetches from OpenSea API (or mock for testnet)
const tokenId = args[0];
const contractAddr = args[1];
const response = await Functions.makeHttpRequest({
  url: `https://api.opensea.io/api/v2/asset/${contractAddr}/${tokenId}`,
  headers: { "X-API-KEY": secrets.OPENSEA_API_KEY }
});
const floorPrice = response.data.collection.stats.floor_price;
return Functions.encodeUint256(Math.round(floorPrice * 1e8)); // 8 decimals
```

#### [MODIFY] `guardian/riskEngine.js`
- `evaluateL1_ValueDrain` reads valuation from `FairValueGuard.getLatestValuation()` via `ethers` call instead of the raw `usdValue` body field

#### [NEW] `chainlink-functions/README.md`
Step-by-step: create subscription, fund with LINK, add consumer contract, deploy.

> [!IMPORTANT]
> Chainlink Functions requires a funded LINK subscription on the target network (Scroll Sepolia). The subscription ID must be set in `FairValueGuard`'s constructor. For testnet, we will use a mock fallback so tests still pass without live LINK.

## Task 4 — Market Research: Decentralized In-Game Asset Markets

### What this produces
A comprehensive `MARKET_RESEARCH.md` document covering the competitive landscape.

| Platform | Chain | Model | In-Game Assets | Fees | API |
|---|---|---|---|---|---|
| OpenSea | ETH, Polygon, Solana | Order Book | Yes (skins, land) | 2.5% | Yes |
| Immutable X | ETH L2 (StarkEx) | Order Book | Yes — native gaming | 0% gas, 2% protocol | Yes |
| Enjin | ETH, Polkadot | Fixed Price | Yes — ENJ backed | Variable | Yes |
| DMarket | ETH sidechain | P2P + Auction | Yes — CS:GO, Dota | 5-7% | Yes |
| Rarible | Multi-chain | Order Book | Limited | 1% | Yes |
| Magic Eden | Solana, ETH | Order Book | Growing | 2% | Yes |

**Key insight documented:** All existing platforms use **order-book** or **fixed-price listing** models. DMEX is unique in offering **atomic barter** (multi-asset, multi-standard, no price discovery needed) — this is a structural gap none of these platforms fill.
